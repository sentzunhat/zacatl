## Gotchas learned from the 0.0.58 cycle — read before starting

- **Don't re-enable `enforce_admins` or `required_conversation_resolution`** on `main`'s branch
  protection. Both default ON if `github-repo-hardener` (or similar) is re-run; beltrd explicitly wants
  them OFF. See `.hawp/kit`-adjacent memory / `release-security-baseline` if you have access to it, or
  just check `gh api repos/sentzunhat/zacatl/branches/main/protection` before assuming either is off.
- **`npm audit` and GitHub's Dependabot alerts don't always agree in real time.** Cross-check both
  before believing a CVE is fixed or unfixed.
- **`overrides` in `package.json` only apply to the package.json that declares them** — a consumer
  installing via `file:../../` (the example apps) does NOT inherit root's `overrides`. If a transitive
  CVE fix needs to reach the examples, add the same scoped override to each affected example's own
  `package.json` too, and regenerate that example's lockfile.
- **Doc code snippets drift from the workflows they describe.** If you touch `.github/workflows/ci.yml`
  concurrency, matrix, or trigger conditions, grep `docs/guidelines/ci-cd-workflow.md` for the same
  values and update both together.
- **PR descriptions go stale fast** when a PR lives across many follow-up commits — re-read the
  description against current code before merging, don't trust what was written on open.
- **`EOTP` on `npm publish` in CI means the token isn't an Automation-type token** (or account 2FA
  policy is stricter than that) — it's not something fixable from workflow YAML; it needs a new token
  or npm Trusted Publishing (OIDC) config on npmjs.com. No git/tag change is needed to retry — just
  re-run `gh workflow run release.yml --ref v0.0.59` once the token's fixed.
