## Revised plan: layered child containers

### Architecture

```
global tsyringe container   ← ORM tokens registered here (unique vendor+name tokens, no collision)
  └── serviceContainer      ← one per Service instance; created in service.ts constructor
        └── infraContainer  ← repos registered here; child of serviceContainer
              └── domainContainer  ← domain services here; inherits repos via parent chain
                    └── appContainer  ← handlers here; inherits services + repos via chain
```

tsyringe child containers inherit parent registrations (child can resolve parent's tokens; parent
cannot see child's). This mirrors the hexagonal dependency flow exactly:
- Application depends on Domain (appContainer is a child of domainContainer)
- Domain depends on Infrastructure (domainContainer is a child of infraContainer)
- Infrastructure depends on Platform (infraContainer is a child of serviceContainer)

ORM instance tokens remain in the global container because they already use unique vendor+name
tokens (`createDatabaseToken(vendor, connectionName)`) — two Service instances with different
named connections don't collide. Two Services with the same unnamed vendor token is the edge
case; that was already documented and is out of scope for this item.

### Files changed

- `src/dependency-injection/container.ts` — add `createChildContainer(parent?)` and optional
  `container` param to `ensureRegisteredSingleton`, `registerDependencies`, `resolveDependencies`,
  `registerValue`. Keep all existing zero-arg exports for back-compat (fall through to global).
- `src/service/layers/layers.ts` — create the 3 child containers and pass each to its layer class.
- `src/service/layers/infrastructure/infrastructure.ts` — accept + use `infraContainer`.
- `src/service/layers/domain/domain.ts` — accept + use `domainContainer`.
- `src/service/layers/application/application.ts` — accept + use `appContainer`.
- `src/service/service.ts` — create `serviceContainer = tsyringeContainer.createChildContainer()`,
  pass to `new Layers(layers, serviceContainer)`.
- `src/service/platforms/server/server.ts` — remove 5 passthrough getters, update tests.
- `test/unit/service/platforms/server/server.test.ts` — refactor to test behavior not internals.
- `test/unit/` — add two-Service-instances-in-one-process isolation test.

### Risk

Medium. The change is cross-cutting (touches all layer constructors) but the logic in each file
is small. The global container remains the fallback in all public `@zacatl/dependency-injection`
exports, so external consumers using standalone DI helpers are unaffected. The main risk is an
edge case where a consumer resolves from the global container directly (e.g., in tests that call
`resolveDependency(SomeClass)` after `new Service(...)`) — those will miss the child-container
registrations. The fix there is to use the container returned by the layer instead.
